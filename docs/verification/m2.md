## Corrections and remaining limits

- An M1 test expected a missing database parent directory to fail. M2 explicitly requires creating it, so that test now uses an invalid database target (a directory) for failure; new integration coverage asserts successful directory creation.
- Build checks caught a shadowed session-count assignment and constructor initialization ordering in new controllers; both were corrected before passing the final suite.
- Existing signed-runtime and OneDrive/Maven cleanup constraints remain documented in README; no OS security settings were changed.
- Profile storage remains singleton per data directory. Local subject/workspace/application metadata does not imply cloud or multi-account ownership.
- JSON replacement is deliberately not merge; export requires a fresh `.json` filename outside the app data root. Backups are unencrypted and retained for recovery. Very large snapshots beyond the documented limits are rejected.
- Full resource/workspace/task/session editors, timer/history workflows, paging, reward calculations, Windows enforcement and packaged distribution remain later work. Achievement records store facts only. Imported unfinished sessions are interrupted and application selections remain inactive.

Only M2 was implemented. Commit identity and hash are checked with Git and reported in the completion message.
